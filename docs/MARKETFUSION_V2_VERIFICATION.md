# Проверка MarketFusion V2 — 15 ноября 2026

Ветка `feature/marketfusion-v2`, исходный commit `c2042cc`, целевая ветка PR — `feature/core-integration`. Production не обновлялся. Полное ТЗ: [требования](MARKETFUSION_V2_REQUIREMENTS_RU.md), [аудит](MARKETFUSION_V2_AUDIT.md), [API](MARKETFUSION_V2_API.md), [запуск и откат](MARKETFUSION_V2_RELEASE.md).

## Реализовано

- Единые модели товара, варианта, предложения и доставки; деньги в целых копейках, валюта отдельно. Нормализация русских названий и ограниченных опечаток. Конфликты модели, объёма, цвета, комплектации и состояния исключают точное совпадение; текстовое сходство само по себе его не доказывает. Достоверность зависит от полноты данных источника; универсальное распознавание всех категорий не заявляется.
- Асинхронный поиск с частичными результатами и отменой. Десять адаптеров используют существующий коннектор; кэш, тайм-ауты и временное отключение ошибающегося источника. Две операции с источниками на все процессы через PostgreSQL advisory locks; до пяти активных заданий в процессе, по одному на пользователя. Подключение нового разрешённого API возможно через `register_source`, без замены движка.
- Точный вариант сравнивается отдельно от похожих. Обычная цена, условные скидки и доставка разделены. Неизвестная доставка не равна бесплатной; итог считается только для подтверждённой доставки в выбранный регион. Разные валюты не пересчитываются выдуманным курсом.
- Постоянные PostgreSQL-каталог, поиски, избранное, профиль, измерения и наблюдения; серверная проверка владельца. Старые избранные сохраняются, их давняя цена не выдаётся за текущую. Миграции версионированы и сериализованы. Старые текстовые наблюдения и история сохраняются, наблюдения приостановлены с `needs_selection` до выбора варианта.
- Наблюдение за конкретным вариантом или предложением, семь условий, cooldown и hysteresis, leases и устойчивые события. При неизвестном исходе отправки Telegram событие остаётся в приложении, повторная автоматическая отправка не выполняется во избежание дубля. Гарантия exactly-once для внешнего Bot API не заявляется.
- Telegram: одно приветствие, удаление старой Reply Keyboard, контекстные кнопки, общий поиск, отдельная обработка фотографий, сохранение старых отзывов/ИИ/избранного. Mini App/Web: четыре вкладки, темы, фильтры, частичная выдача, карточка, история, наблюдения и администрирование по серверной роли. Убраны поддельная Telegram-личность и очистка всей sessionStorage при старте.
- Сохранены маршруты LLM/vision и зашифрованные настройки. Учёт реально возвращённых провайдером input/output tokens по пользователю, модели и задаче, административная сводка. Без тарифов денежная стоимость не вычисляется; если провайдер не возвращает usage, это не считается доказанным нулевым расходом.

## Автоматические и локальные проверки

Команды и условия воспроизведения приведены в инструкции запуска. Итоговые количества тестов записаны в PR и `.memory/CURRENT_STATE.md` после финального прогона.

| Проверка | Что подтверждает | Чего не подтверждает |
|---|---|---|
| Python unit/integration | Различение NV3 500GB/1TB/2TB/NV2, нормализация, exact-only минимум, доставка 4800+500 против 5000+0, старый matcher, доступ владельца, CSRF, Telegram routing | Доступ к реальным площадкам |
| Настоящая отдельная PostgreSQL | Одновременная миграция, сохранение старых данных, leases, семь правил, outbox, HTTP→поиск→worker→событие, сохранность после переподключения, общий лимит источников | Поведение production БД под нагрузкой |
| Worker со входными фикстурами | 5500→4900→4900 создаёт одно событие; другой объём и регион не участвуют; чужой пользователь не получает watch | Реальная доставка сообщения Telegram |
| Четыре Playwright-сценария с API-фикстурами | Веб-вход, четыре вкладки, промежуточная выдача и ошибка Ozon, выбор варианта/порог, отмена, неизвестная доставка | Реальные цены и клиент Telegram |
| TypeScript и Vite | Типы и production-сборка фронтенда | Полная продуктовая приёмка |
| Docker staging с реальными API/PostgreSQL | Вход, HttpOnly cookie, четыре вкладки, защищённая статистика ИИ, health без demo, отсутствие JS-ошибок и горизонтального переполнения на 390px | Поиск маркетплейсов, LLM или бот: они не запускались этим smoke-тестом |
| `pg_dump`→`pg_restore` staging | Восстановление схемы и совпадение счётчиков: 0 users, 0 favorites, 0 watches, 2 migrations | Восстановление реального пользовательского архива production; staging исходно пустой |

Снимок Docker после входа и просмотра администрирования: API 211 MiB, Web 10 MiB, PostgreSQL 69 MiB. Это короткий локальный smoke без Chrome, bot и worker, а не результат нагрузочного испытания всего стека. Лимит staging API — 384 MiB, Chrome — 768 MiB. Сумма предельных бюджетов всего стека превышает 1 ГБ RAM текущего VPS. Перед production обязателен нагрузочный прогон с единственным Chrome и контролем swap/OOM; для запаса рекомендуется 2 ГБ RAM. Расходы и изменение тарифа не выполнялись и не разрешены.

В V2 эти состояния видны пользователю; цены не берутся из фикстур или поисковых сниппетов. Бесплатный подтверждённый маршрут ко всем площадкам не найден. Новых платных подписок, прокси и обращений поставщикам нет.

## Остаётся перед полной приёмкой

1. Повторить V2 live-проверки на разрешённом тестовом стенде с нужным браузерным маршрутом; подтвердить один идентичный вариант хотя бы на двух площадках. Текущие коннекторы не заполняют доказанный регион: региональный watch отклоняется с понятной ошибкой, а не работает по случайной цене. Нужны данные источника, подтверждающие регион, наличие и доставку.
2. Проверить V2 `/start`, callbacks, фото, отзывы, живой LLM/vision и реальное уведомление Telegram. Старое подтверждение владельца «бот и Mini App работают» относится к прежней версии.
3. Восстановить DNS-цены и доступ к семи ограниченным источникам. Поддержка API в архитектуре не означает наличие доступа к нему. Лицензии и происхождение компонентов описаны в `SOURCES.md`; Grex/PriceWatch без лицензий не копировались.
4. Проверить нагрузку полного стека на ресурсы VPS; воспроизвести восстановление копии production до обновления. Получить отдельное разрешение владельца по §14 ТЗ.

Это реализованная и локально проверенная ветка модернизации с открытыми внешними критериями. Готовность полного MVP по всем площадкам и production-приёмка не заявляются.
