# Поиск открытых решений для источников цен — 15 ноября 2026

## Что воспроизведено на нашем VPS

На `48.103.149.93` прямой WB JSON-поиск `search.wb.ru` вернул HTTP 403, после чего существующий коннектор прочитал 40 карточек через Chrome. В общей выдаче первые пять имели только цену WB Кошелька, поэтому обычная цена оставалась пустой. Проверка одной из этих карточек (`nmId 2124848933`) через тот же Chrome вернула **3 284 ₽ обычной цены** и **3 185 ₽ с WB Кошельком**. После внедрения проверки одной карточки в общий поиск живой запрос вернул одну обычную цену WB, но предыдущая попытка не получила ни одной карточки из поиска. Маршрут работает только при доступной выдаче и пока нестабилен.

По другим площадкам живой результат на новом VPS остаётся прежним: Ozon и Avito блокируют обращения, DNS и другие источники отвечают тайм-аутом или блокировкой. Обзор [статуса источников](MVP_SOURCE_STATUS_RU.md) отделяет эти ошибки от парсинга и отсутствия обычной цены.

## Практический вывод

Первый проверенный исправляемый дефект — обычная цена WB на карточке — закрывается средствами уже установленного коннектора. Для Ozon/Avito нельзя обещать работу от установки другого GitHub-парсера: сторонние проекты тоже зависят от доступа к площадке и часто прямо требуют подходящий IP или браузерную сессию. Домашний маршрут мог бы быть бесплатным диагностическим вариантом, но для круглосуточного MVP устройство должно оставаться включённым и доступным; пока этот вариант не настроен.

Следующий цикл: проверить WB после развёртывания, затем отдельно измерить для каждого заблокированного источника статус HTTP, ответ браузера, время и наличие цены. Не смешивать карточку товара, условную цену и подтверждённую обычную цену.
# Дополнительная проверка 15 ноября: наблюдение ответа WB

Прямая CDP-проба на текущем VPS получила HTTP 200 от `www.wildberries.ru/__internal/u-search/exactmatch/ru/common/v18/search`: 100 товаров по `ssd`. У первого товара `sizes[].price.product=410600`, то есть 4106 ₽, что совпало с ранее проверенной обычной ценой карточки. Это обосновывает чтение ответа, который загрузила сама страница, без повторного вызова защищённого API из Python. Реализация принимает только same-origin ответ с совпадающими query/page, хранит только публичные поля каталога и сохраняет DOM-путь при отсутствии ответа.
