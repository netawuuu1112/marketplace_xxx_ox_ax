# MarketFusion MVP: проверяемые источники и функции

## Цель

Довести существующий проект до состояния, в котором поиск, сравнение, анализ отзывов и мониторинг возвращают реальные данные, а бот и Mini App показывают одинаковое состояние и явно называют недоступные источники. Демо-товары не должны попадать в рабочую выдачу.

## Текущее устройство

- `GET /api/marketplaces/search` вызывает `compare_connector.compare_prices`; модуль опрашивает до десяти товарных источников и возвращает `source_outcomes` и признак полноты.
- Бот и `/api/search`, `/api/compare`, `/api/reviews` используют отдельный контракт `backend/adapters` для Ozon, Яндекс Маркета и WB. Мониторинг использует `compare_connector`. Эти два пути требуют согласования, чтобы пользовательские функции работали с теми же предложениями.
- Другие подключённые модули: Циан (недвижимость, отдельная модель объявления) и MPStats (платная аналитика по SKU). Их нельзя выдавать за обычный товарный поиск.

## Критерии приёмки

1. Для каждого установленного источника есть измеренный результат самопроверки из работающего окружения: `healthy`, `blocked`, `auth_missing` или ошибка схемы; тесты с фикстурами не считаются живой проверкой.
2. Источники с браузерным маршрутом получают выделенный Chrome по внутренней сети Docker. Порт CDP недоступен снаружи VPS; профиль браузера отдельный и сохраняется между перезапусками. Отказ браузера не роняет API, бота и worker.
3. Для каждого источника показываются время измерения, регион и статус; если цена не получена, сравнение остаётся неполным. Цена по подписке не ранжируется как обычная, а разные варианты товара не объявляются идентичными без подтверждения.
4. Поиск, сравнение, отзывы/анализ, избранное и наблюдение за ценой проверяются через HTTPS и Telegram-клиент на реальных ответах. Мониторинг создаёт уведомление только при подтверждённом пересечении порога и не заменяет отказ источника ценой 0.
5. Административные роли и функции UI соответствуют ограничениям API. Расширение Chrome использует общее избранное/наблюдение после явного входа. Секреты остаются вне Git.

## Ограничения доступа

Пользователь выбрал работу без новых расходов и запретил отправлять обращение поставщику. Поэтому MPStats и коммерческие API не подключаются без нового решения пользователя. Для Ozon, WB, Авито и других площадок браузер и IP сервера могут оказаться недостаточными; такой статус фиксируется как внешний блокер, а не маскируется демо-данными. Лицензия на исходники коннектора не является лицензией на товарные данные для публичного показа.

## Первые этапы

1. Снять матрицу самопроверок на VPS и обеспечить воспроизводимые локальные тесты.
2. Добавить необязательный изолированный Chrome-сервис в Docker Compose и повторить самопроверки. Если IP остаётся заблокированным, сохранить честный статус и не включать неисправный источник как рабочий.
3. Согласовать модели и UI для всех товарных источников, не смешивая Циан и MPStats с обычным сравнением.
4. Проверить каждый пользовательский сценарий и закрыть выявленные дефекты с регрессионными тестами; только после этого обозначать MVP готовым.
